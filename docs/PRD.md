# PRD: キャリボト Web マッププロジェクト

## 0\. Overall Summary

* 本プロダクトは、阪大内の給水機の場所・稼働状態・水温種別を確認できる給水機マップWebアプリである。  
* 初回リリースでは機能を最小限に絞り、豊中・吹田・箕面キャンパスを対象に、2026年度中のWebアプリ公開とプロトタイピングを行う。  
* 今年中のマイハンダイ掲載は難しい見込みだが、2027年度以降に認可がおりやすくなるよう、Webアプリとして利用実績・運用実績・改善実績を作る。  
* 地図SDKは当面使用せず、阪大公式キャンパスマップを参考に生成した地図画像を用いる。  
* キャリボトがキャンパスに設置する給水機にはQRコードを貼り、ユーザーがQRコードを読み取って地図アプリにアクセスできるようにする。  
* QRコードに埋め込むリンクは直接URLではなく短縮リンクを挟むことで、リリース後にリンク先を変更できるようにする。  
* 短縮リンクには、GDG Japan の `url.gdgs.jp` を使用可能とする。  
* 給水機マップWebアプリとは別に、キャリボトの活動・給水機プロジェクト・マイボトル利用促進を紹介するLPサイトも作成する。  
* デザインはキャリボト作成のStitchの雰囲気を反映しつつ、具体的なページ構成やUIレイアウトはGDG主導で調整する。

## 2\. Problem Statement

### Current Situation

* 阪大内には給水機が設置されているが、学生・教職員にとって設置場所が十分に分かりやすく共有されていない。  
* 給水機の稼働状態、停止状態、故障状態、冷水・常温水・温水などの水温種別が一元的に確認できる仕組みがない。  
* 給水機の設置希望場所を学生から収集し、キャンパスごとに可視化する仕組みがない。  
* 故障や異常を給水機単位で報告するための導線が不足している。  
* 給水機の現地利用者が、その場で地図アプリや関連情報にアクセスするための導線が不足している。  
* 今年中のマイハンダイ掲載は難しそうだが、来年以降に認可がおりやすくするための実績を作ることを目的に、2026年度にWebアプリとしてリリースし、プロトタイピングを行う。  
* 阪大広報課は返信や対応などのスピードが遅く、マイハンダイ対応が遅れている一因になっている。  
* 初期登録する給水機の台数と場所一覧はまだ確定しておらず、キャリボトに確認中である。

### Pain Points

* 利用者が最寄りの給水機の場所を把握しづらい。  
* 現在地と給水機の位置関係が分からない。  
* 給水機が利用可能か、停止中か、故障中かが事前に分からない。  
* 冷水・常温水・温水のどれが利用できるか分からない。  
* 設置希望のニーズを収集する仕組みがない。  
* 設置希望リクエストをキャンパスごとに整理して確認できない。  
* 緊急連絡先が分かりづらく、故障・異常の報告導線が弱い。  
* 給水機の現地利用者が、関連する地図アプリやキャリボト情報へすぐにアクセスできない。  
* マイハンダイ掲載に向けた実績や検証材料が不足している。

### Why Now

* 2026/04/08 に「ゆるワニ博士タンブラー」が象印・広報課・生協と連携して販売され、給水機利用促進の必要性が高まっている。  
* 将来的なマイハンダイ掲載を目指す上で、Webアプリとして先行リリースし、実績を作る必要がある。  
* 給水機の新規設置は今後増える可能性があり、管理画面を含む運用基盤を早期に整備する価値がある。  
* 給水機にQRコードを貼ることで、給水機の現地利用者を地図アプリやキャリボトLPサイトへ誘導できる。  
* 短縮リンクを利用することで、QRコードを貼り替えずにリンク先を変更でき、リリース後の運用変更に対応しやすくなる。  
* 初回リリースでは機能を最小限に絞り、主要機能が動く状態を早期にキャリボトへ提示し、改善点を得る。

* 阪大の豊中・吹田・箕面キャンパスすべてを初期対象にする。  
* 研究棟・部局管理エリアも対象に含める。  
* 給水機の設置場所を地図画像上で確認できるようにする。

  * 常温水

  * 停止中  
  * 故障中

  * キャンパス  
  * 建物  
  * コメント

* 階数や詳細な場所はコメントで入力できるようにする。  
* 希望調査画面のリクエスト状況リストをキャンパスごとにまとめて表示する。  
* 設置希望リクエストは他ユーザーにも公開する。  
* 緊急連絡フォームを提供する。  
* 緊急連絡フォームの送信先は `carry.my.bottle@gmail.com` とする。  
* 緊急連絡後、ユーザーに送信完了メールまたは自動返信を送る。  
* 管理画面を提供する。  
* 管理画面はキャリボト管理者が利用する。  
* キャリボトのホームページへの導線を用意する。  
* キャリボトのLPサイトを作成する。  
* LPサイトから給水機マップWebアプリへ遷移できるようにする。  
* LPサイト上でキャリボトの活動概要、給水機プロジェクトの背景、マイボトル利用促進の目的を説明する。  
* LPサイト上にキャリボトへの問い合わせ導線または関連リンクを設置する。  
* キャリボトがキャンパスに設置する給水機にQRコードを貼り、ユーザーがQRコードを読み取って地図アプリにアクセスできるようにする。

* 短縮リンクには、GDG Japan の `url.gdgs.jp` を使用可能とする。  
* スマートフォン優先で実装しつつ、レスポンシブ対応も行う。  
* Stitchデザインの雰囲気を反映する。  
* 初回リリースでは、主要機能が動くことと、キャリボトから改善点を得ることを成功条件とする。

### Non-Goals

* 初期リリースでは、地図SDKは使用しない。  
* 初期リリースでは、Google Maps API、Mapbox、OpenStreetMap等を使った本格的なインタラクティブ地図は実装しない。  
* 初期リリースでは、「一番近い給水機」を自動表示する機能は実装しない。  
* 初期リリースでは、給水機までのルート案内は実装しない。  
* 初期リリースでは、音声案内は実装しない。  
* 初期リリースでは、給水量の自動取得は実装しない。  
* 初期リリースでは、給水機へのマイコン組み込みやIoT連携は実装しない。  
* 初期リリースでは、阪大外への展開は対象外とする。  
* 初期リリースでは、マイハンダイへの正式統合は対象外とする。  
* 初期リリースでは、QRコードごとに高度な個別分析やA/Bテストを行わない。  
* 技術スタック、デプロイ先、ドメイン、メール送信基盤、データ初期登録、運用責任範囲などの技術詳細はDesign Docで決定する。

## 4\. Target Users

* **阪大学生**  
  * 大学内で給水機を利用したいユーザー。  
  * 現在地と給水機の位置関係を把握したい。  
  * 使える給水機、停止中の給水機、水温種別を知りたい。  
  * 給水機を設置してほしい場所に投票したい。  
  * 給水機に貼られたQRコードを読み取り、地図アプリや関連情報にアクセスしたい。  
* **阪大教職員**  
  * キャンパス内で給水機を利用したいユーザー。  
  * 利用可能な給水機の場所を確認したい。  
  * 給水機に貼られたQRコードから、給水機マップやキャリボトの情報にアクセスしたい。  
* **キャリボト管理者**  
  * 給水機情報を管理したい。  
  * 稼働状態、故障状態、水温種別などを更新したい。  
  * 設置希望リクエストを確認したい。  
  * 緊急連絡を受け取りたい。  
  * 給水機に貼るQRコードを通じて、ユーザーを地図アプリへ誘導したい。  
* **部局担当者**  
  * 将来的に、部局ごとの給水機管理や連絡先管理に関与する可能性がある。  
  * 初期リリース時点では、部局・給水機・通知先の対応表は未整備。  
* **阪大広報課**  
  * 将来的なマイハンダイ掲載に関与する可能性がある。  
  * 初期リリースでは直接の主要ユーザーではなく、将来的なステークホルダーとして扱う。

## 6\. Requirements

### Functional Requirements

* **FR-001: Static Campus Map Display**  
  * 阪大公式キャンパスマップを参考に生成した地図画像を表示する。  
  * 初期対象は豊中・吹田・箕面の全キャンパスとする。  
  * 地図SDKは使わない。  
  * コストカットとデザイン性向上を重視する。  
* **FR-002: Water Station Pin Display**  
  * 地図画像上に給水機の位置を表示する。  
  * 給水機の位置はピンまたはそれに相当する視覚要素で表示する。  
  * ピンは水温種別や状態が分かるデザインにする。  
* **FR-003: Current Location-like Display**  
  * Googleマップのように、現在地が分かるような体験を提供する。  
  * ただし、地図SDKを使わないため、実装方式はDesign Docで検討する。  
  * 初期リリースでは「最寄り給水機の自動算出」や「ルート案内」は含めない。  
* **FR-004: Water Station Status Display**  
  * 給水機ごとに利用可能かどうかの状態を表示する。  
  * 表示対象の状態は少なくとも以下とする。  
    * 利用可能  
    * 停止中  
    * 故障中  
* **FR-005: Water Temperature Type Display**  
  * 給水機ごとに水温種別を表示する。  
  * 水温種別は以下とする。  
    * 冷水  
    * 常温水  
    * 温水  
* **FR-006: Water Station Detail View**  
  * 給水機を選択すると詳細情報を表示する。  
  * 詳細情報には最低限以下を含める。  
    * キャンパス  
    * 建物  
    * 利用可能状態  
    * 水温種別  
    * 緊急連絡フォームへの導線  
* **FR-007: Installation Request and Voting**  
  * 給水機設置希望場所の投票機能を提供する。  
  * 投稿と投票のログイン要否、投票制限、識別方式はOpen Questionsとする。  
  * 初期リリースでは最小限の投稿・投票体験を優先する。  
* **FR-008: Installation Request Location Granularity**  
  * 設置希望場所の粒度は以下とする。  
    * キャンパス  
    * 建物  
    * コメント  
  * 建物はU2棟などの粒度で選択できるようにする。  
  * 階数や詳細な場所はコメントで入力する。  
* **FR-009: Building Tabs**  
  * 設置希望画面では、建物をタブ形式で表示する。  
  * 建物一覧は、更新頻度が低いためGDG側がハードコードまたはDBで管理する。  
  * ハードコードとDBのどちらにするかはDesign Docで決定する。  
* **FR-010: Campus-grouped Request List**  
  * 希望調査画面のリクエスト状況リストはキャンパスごとにまとめて表示する。  
  * 設置希望リクエストは他ユーザーにも公開する。  
* **FR-011: Emergency Contact Form**  
  * 各給水機に対して緊急連絡フォームを提供する。  
  * 送信先メールアドレスは `carry.my.bottle@gmail.com` とする。  
  * フォーム送信後、ユーザーに送信完了メールまたは自動返信を送る。  
  * 写真添付の要否、入力項目、issue typeの設計はOpen Questionsとする。  
* **FR-012: Admin Console**  
  * キャリボト管理者向けの管理画面を提供する。  
  * 管理画面では、少なくとも給水機情報を管理できるようにする。  
  * 管理画面のログイン方式は以下のどちらかを候補とする。  
    * 管理者パスワード  
    * GDG共通認証基盤 `accounts.gdgs.jp`  
  * 最終方式はDesign Docで決定する。  
* **FR-013: Cariboto Website Link**  
  * キャリボトのホームページへの導線を設置する。  
  * 導線の配置はUI設計時に決める。  
* **FR-014: Responsive UI**  
  * スマートフォン優先で設計する。  
  * 工数が小さい範囲でレスポンシブ対応を行う。  
  * PCでも最低限利用可能な表示にする。  
* **FR-015: Stitch Design Direction**  
  * キャリボト作成のStitchデザインの雰囲気を反映する。  
  * 具体的なページ構成、UIレイアウト、管理画面、緊急連絡フォーム、設置希望一覧はGDG主導で調整する。  
* **FR-016: Cariboto Landing Page**  
  * キャリボトのLPサイトを作成する。  
  * LPサイトには最低限以下を含める。  
    * キャリボトの活動概要  
    * 給水機マップへの導線  
    * 給水機プロジェクトの背景  
    * マイボトル利用促進に関する説明  
    * 問い合わせ導線または関連リンク  
  * LPサイトはスマートフォン優先で設計する。  
  * 給水機マップWebアプリと同一プロジェクト内で扱うか、別ページとして扱うかはDesign Docで決定する。  
* **FR-017: QR Code Access from Water Stations**  
  * キャリボトがキャンパスに設置する給水機にQRコードを貼る。  
  * ユーザーはQRコードを読み取ることで、給水機マップWebアプリにアクセスできる。  
  * QRコードは、給水機の現地利用者が地図アプリや関連情報へアクセスするための主要導線の一つとする。  
  * QRコードの設置対象は、キャリボトがキャンパスに設置する給水機とする。  
* **FR-018: Short Link for QR Code**  
  * QRコードに埋め込むリンクは、アプリの直接URLではなく短縮リンクを挟む。  
  * 短縮リンクを利用することで、リンク先の変更に対応できるようにする。  
  * 短縮リンクには、GDG Japan の `url.gdgs.jp` を使用可能とする。  
  * 短縮リンクのリンク先は、初期リリース時点では給水機マップWebアプリを想定する。  
  * LPサイトを経由させるか、給水機マップへ直接遷移させるかはOpen Questionsとする。

### Non-Functional Requirements

* **Scope**  
  * 初期リリースでは阪大内のみを対象とする。  
  * 豊中・吹田・箕面の全キャンパスを対象とする。  
  * 研究棟・部局管理エリアも含める。  
* **Performance**  
  * スマートフォンで快適に閲覧できる表示速度を目指す。  
  * 地図SDKを使わず画像ベースとすることで、初期表示の軽量化を図る。  
  * QRコード読み取り後、スマートフォン上でスムーズにページが開けることを重視する。  
* **Security**  
  * 管理画面は認証されたキャリボト管理者のみアクセスできるようにする。  
  * 認証方式はDesign Docで決定する。  
  * 短縮リンクの管理権限は、信頼できるGDGまたはキャリボト関係者に限定する。  
* **Privacy**  
  * 現在地情報を扱う場合、必要最小限の利用にとどめる。  
  * 位置情報を保存するかどうかはDesign Docで明示する。  
  * 初期方針として、不要な位置情報保存は避ける。  
* **Maintainability**  
  * 給水機情報を管理画面から更新できるようにする。  
  * 建物一覧は更新頻度が低いため、ハードコードまたはDB管理とする。  
  * どちらを採用するかはDesign Docで決定する。  
  * QRコードのリンク先を変更できるよう、短縮リンクを利用する。  
  * QRコードを再印刷・再設置せずに、遷移先URLを変更できる運用を前提とする。  
* **Scalability**  
  * 将来的な給水機増加に対応できる設計にする。  
  * 2027年度以降に新規設置が加速する可能性を考慮する。  
  * 将来的な部局別通知先管理に拡張できる余地を残す。  
  * 給水機ごとに個別QRコードを発行するか、共通QRコードを利用するかはDesign Docで検討する。  
* **Accessibility**  
  * スマートフォンで読みやすく、操作しやすいUIにする。  
  * ピンやステータス表示は色だけに依存しすぎない設計を検討する。  
  * QRコードの掲示物には、必要に応じて短い説明文や代替URLを併記する。  
* **Design Consistency**  
  * Stitchの雰囲気を反映する。  
  * ただし、MVP実装では実装コストと操作性を優先する。  
  * QRコード掲示物のデザインは、アプリ・LPサイトのデザインと大きく乖離しないようにする。

## 7\. User Experience

### Main User Flow: Find a Water Station

* ユーザーがWebアプリを開く。  
* キャンパスマップ画像が表示される。  
* 給水機の位置が地図画像上に表示される。  
* ユーザーは現在地が分かるような表示を確認する。  
* ユーザーが給水機のピンまたは表示要素を選択する。  
* 給水機の詳細情報が表示される。  
* ユーザーは以下を確認する。  
  * 給水機の場所  
  * 利用可能状態  
  * 停止中かどうか  
  * 故障中かどうか  
  * 冷水・常温水・温水の種別  
  * 緊急連絡フォームへの導線

### Main User Flow: Access from QR Code

* ユーザーがキャンパス内に設置された給水機を見つける。  
* 給水機に貼られたQRコードをスマートフォンで読み取る。  
* QRコードに埋め込まれた短縮リンクにアクセスする。  
* 短縮リンクから給水機マップWebアプリへ遷移する。  
* ユーザーは現在の給水機周辺の情報や、他の給水機の場所を確認する。  
* 必要に応じて、設置希望、緊急連絡、キャリボトLPサイトへの導線を利用する。

### Main User Flow: Submit or Vote for Installation Request

* ユーザーが設置希望画面を開く。  
* キャンパスを選択する。  
* 建物タブから設置希望場所を選択する。  
* 必要に応じて、階数や詳細場所をコメントで入力する。  
* 設置希望を投稿または投票する。  
* 投稿・投票内容がリクエスト状況に反映される。  
* リクエスト状況はキャンパスごとに表示される。  
* 他ユーザーもリクエスト状況を確認できる。

### Main User Flow: Emergency Contact

* ユーザーが給水機詳細画面を開く。  
* 緊急連絡フォームを開く。  
* 故障・停止・異常などの内容を入力する。  
* フォームを送信する。  
* `carry.my.bottle@gmail.com` に通知が送られる。  
* ユーザーに送信完了メールまたは自動返信が送られる。

### Main User Flow: Visit Cariboto Landing Page

* ユーザーがキャリボトLPサイトを開く。  
* キャリボトの活動概要を確認する。  
* 給水機プロジェクトの背景を確認する。  
* マイボトル利用促進の目的を確認する。  
* 給水機マップへのリンクまたはCTAを選択する。  
* 給水機マップWebアプリに遷移する。

### Admin Flow

* キャリボト管理者が管理画面にアクセスする。  
* 認証を行う。  
* 給水機情報を追加・編集・更新する。  
* 稼働状態、水温種別、故障状態、停止状態などを更新する。  
* 必要に応じて設置希望リクエストを確認する。

### Short Link Management Flow

* GDGまたは管理権限を持つ担当者が `url.gdgs.jp` で短縮リンクを作成する。  
* 作成した短縮リンクをQRコードに埋め込む。  
* キャリボトが給水機にQRコードを掲示する。  
* リンク先を変更する必要が生じた場合、QRコード自体は変更せず、短縮リンク側の遷移先を更新する。  
* ユーザーは同じQRコードを読み取るだけで、更新後のリンク先へアクセスできる。

## 8\. Business Requirements

### Business Objective

* 給水機の利用促進を行う。  
* マイボトル利用文化を広げる。  
* 給水機の設置場所を分かりやすく周知する。  
* 給水機設置希望のニーズを可視化する。  
* キャリボトの活動内容を分かりやすく発信する。  
* 給水機マップWebアプリの利用導線を整備する。  
* 給水機に貼ったQRコードから、現地利用者をWebアプリへ誘導する。  
* QRコードのリンク先変更に対応できるようにし、掲示物の貼り替えコストを下げる。  
* マイボトル利用促進や給水機設置活動への理解を広げる。  
* 将来的な広報課・大学関係者への説明資料としても活用できるWeb上の受け皿を作る。  
* 2026年度中にWebアプリとしてプロトタイピングし、2027年度以降のマイハンダイ掲載に向けた実績を作る。  
* 広報課との調整が遅い状況でも、Webアプリとして独立して価値検証できる状態を作る。

### Success Metrics

* 初回リリースで主要機能が動くこと。  
* キャリボトから改善点を得られること。  
* 給水機に貼ったQRコードからWebアプリへアクセスできること。  
* 短縮リンクを介してリンク先変更に対応できること。  
* リリース後に以下の指標を追跡できること。  
  * アクセス数  
  * 給水機詳細閲覧数  
  * 設置希望投稿数  
  * QRコード経由のアクセス数

### Key Assumptions

* 初期リリース対象は豊中・吹田・箕面キャンパスすべて。  
* 研究棟・部局管理エリアも対象に含める。  
* 初期登録する給水機一覧はキャリボトに確認中。  
* 給水機の場所は基本的に頻繁には変わらない。  
* 建物一覧の更新頻度は低い。  
* キャリボトがキャンパスに設置する給水機にはQRコードを掲示できる。  
* `url.gdgs.jp` を短縮リンクとして使用できる。  
* 初期リリースでは機能を最小限に絞る。  
* マイハンダイ掲載は2027年度以降を想定する。  
* 広報課対応は遅れる可能性があるため、Webアプリ単体でのリリースを優先する。

## 11\. Risks and Mitigations

* **Risk: 初期給水機データが揃わない**  
  * 影響:  
    * マップとしての価値が下がる。  
  * 対応:  
    * キャリボト確認中の一覧を最優先で確定する。  
    * MVPでは登録済みの給水機のみ表示し、後から管理画面で追加可能にする。  
* **Risk: 地図SDKを使わないため現在地表示の精度や体験が制限される**  
  * 影響:  
    * Googleマップのような正確な現在地・ルート体験は提供できない。  
  * 対応:  
    * 初期リリースでは「現在地が分かるような体験」にスコープを限定する。  
    * 最寄り給水機自動表示やルート案内はNon-Goalsにする。  
* **Risk: 広報課対応が遅れる**  
  * 影響:  
    * マイハンダイ掲載が遅れる。  
  * 対応:  
    * 2026年度はWebアプリとして独立公開し、実績作りを優先する。  
    * マイハンダイ掲載は2027年度以降の目標として扱う。  
* **Risk: 投稿・投票機能で不正投票やスパムが発生する**  
  * 影響:  
    * 設置希望データの信頼性が下がる。  
  * 対応:  
    * ログイン要否、投票制限、識別方式をOpen Questionsとして整理する。  
    * 初期リリースでは最小限の制限で始めるか、簡易的な制限を入れるかを検討する。  
* **Risk: 緊急連絡フォームの入力項目が不足する**  
  * 影響:  
    * 管理者が状況を判断しづらい。  
  * 対応:  
    * MVPでは最小限の入力項目で開始する。  
    * 写真添付やissue type分類はOpen Questionsとして整理する。  
* **Risk: 管理画面のスコープが膨らむ**  
  * 影響:  
    * 6月中旬リリースに間に合わない可能性がある。  
  * 対応:  
    * 初期は給水機情報の管理に限定する。  
    * 高度な権限管理、変更履歴、部局別管理は後回しにする。  
* **Risk: 部局・給水機・通知先の対応表がない**  
  * 影響:  
    * 部局別通知が実装できない。  
  * 対応:  
    * 初期リリースでは `carry.my.bottle@gmail.com` に集約する。  
    * 部局別通知は将来拡張とする。  
* **Risk: QRコードのリンク先が変更される**  
  * 影響:  
    * 給水機に貼ったQRコードが使えなくなる可能性がある。  
  * 対応:  
    * QRコードには直接URLではなく短縮リンクを埋め込む。  
    * `url.gdgs.jp` を利用し、リンク先変更に対応できるようにする。  
* **Risk: 短縮リンクの管理権限が不明確になる**  
  * 影響:  
    * リンク先変更時に対応できない、または誤ったリンク先に変更される可能性がある。  
  * 対応:  
    * Design Docで短縮リンクの管理者、変更手順、権限範囲を定義する。  
* **Risk: QRコード掲示物が剥がれる・汚れる・読み取れない**  
  * 影響:  
    * 現地からアプリへの導線が機能しなくなる。  
  * 対応:  
    * 掲示方法、サイズ、耐久性、代替URL併記を検討する。  
    * QRコードの定期確認を運用項目として検討する。

### Glossary

* **キャリボト**  
  * 給水機設置・マイボトル利用促進に関わる団体。  
* **マイハンダイ**  
  * 阪大の学生向け情報基盤。将来的な掲載先として検討されている。  
* **給水機**  
  * 学内に設置されている冷水・常温水・温水などを提供する設備。  
* **MVP**  
  * Minimum Viable Product。初期リリースで必要最小限の価値を提供するプロダクト範囲。  
* **Design Doc**  
  * 技術構成、実装方針、データ設計、認証、デプロイ、運用などを整理する技術設計文書。  
* **QR Code**  
  * 給水機に掲示し、ユーザーがスマートフォンで読み取ってWebアプリやLPサイトにアクセスするための導線。  
* **Short Link**  
  * QRコードに埋め込む短縮URL。直接URLではなく短縮リンクを挟むことで、リンク先変更に対応しやすくする。  
* **url.gdgs.jp**  
  * GDG Japan の短縮リンクサービス。QRコードに埋め込む短縮リンクとして使用可能。
